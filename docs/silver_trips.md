# Silver: TLC Yellow Taxi Trips

## Назначение

Таблица `lakehouse.silver.trips` содержит типизированные записи
о поездках Yellow Taxi с информацией об источнике и флагами качества.

Silver сохраняет исходные записи без фильтрации и дедупликации.
Правила включения записей в аналитические показатели определяются
отдельно на уровне Gold.

## Источник

Исходные Parquet-файлы TLC, сохранённые в MinIO:

s3://raw/tlc/yellow/year=YYYY/month=MM/sha256=<hash>/<filename>

Один месяц источника может иметь несколько версий с разным SHA-256.
Job обрабатывает конкретную версию файла.

## Grain

Одна строка Silver соответствует одной строке выбранного исходного файла.

В источнике нет идентификатора поездки, который мы подтвердили
как уникальный. Уникальность физической поездки не гарантируется.

Совпадающие строки автоматически не удаляются.

## Схема

### Поля источника

| Исходное поле | Поле Silver | Тип |
|---|---|---|
| VendorID | vendor_id | INT |
| tpep_pickup_datetime | pickup_datetime | TIMESTAMP_NTZ |
| tpep_dropoff_datetime | dropoff_datetime | TIMESTAMP_NTZ |
| passenger_count | passenger_count | BIGINT |
| trip_distance | trip_distance | DOUBLE |
| RatecodeID | rate_code_id | BIGINT |
| store_and_fwd_flag | store_and_fwd_flag | STRING |
| PULocationID | pickup_location_id | INT |
| DOLocationID | dropoff_location_id | INT |
| payment_type | payment_type | BIGINT |
| fare_amount | fare_amount | DECIMAL(18, 2) |
| extra | extra | DECIMAL(18, 2) |
| mta_tax | mta_tax | DECIMAL(18, 2) |
| tip_amount | tip_amount | DECIMAL(18, 2) |
| tolls_amount | tolls_amount | DECIMAL(18, 2) |
| improvement_surcharge | improvement_surcharge | DECIMAL(18, 2) |
| total_amount | total_amount | DECIMAL(18, 2) |
| congestion_surcharge | congestion_surcharge | DECIMAL(18, 2) |
| Airport_fee | airport_fee | DECIMAL(18, 2) |

Все перечисленные поля допускают NULL.

Исходные даты сохраняются без преобразования часового пояса.
Их интерпретация как UTC не предполагается.

Денежные значения округляются до двух знаков после запятой
по правилу HALF_UP и преобразуются в DECIMAL(18, 2).
Отрицательные значения сохраняют знак.

NULL не заменяется на 0. Если ненулевое исходное денежное значение
невозможно преобразовать, job завершается ошибкой до записи таблицы.
NaN и бесконечные денежные значения также считаются ошибкой преобразования.

### Вычисляемые поля

| Поле | Тип | Описание |
|---|---|---|
| pickup_date | DATE | Дата начала поездки |
| duration_seconds | BIGINT | dropoff_datetime − pickup_datetime в целых секундах |

Доли секунды при вычислении duration_seconds отбрасываются.
Если одна из дат отсутствует, результат равен NULL.

### Происхождение данных

| Поле | Тип | Описание |
|---|---|---|
| source_file | STRING | Полный URI исходного Parquet |
| source_sha256 | STRING | SHA-256 исходного файла |
| source_month | DATE | Первый день месяца источника |
| loaded_at | TIMESTAMP | Момент обработки версии файла |

Поля происхождения обязательны.

Например, для файла yellow_tripdata_2024-01.parquet:
source_month = 2024-01-01.

source_month определяется по параметрам загрузки и метаданным источника,
а не по датам поездок. Параметры должны согласовываться с metadata.json.

loaded_at обозначает момент времени; в Spark он отображается в UTC.

## Флаги качества

| Поле | Условие |
|---|---|
| is_outside_source_month | pickup_datetime вне месяца source_month |
| has_missing_passenger_count | passenger_count IS NULL |
| has_zero_passenger_count | passenger_count = 0 |
| has_nonpositive_distance | trip_distance <= 0 |
| has_nonpositive_duration | dropoff_datetime <= pickup_datetime |
| has_negative_total_amount | total_amount < 0 |

Флаги имеют тип BOOLEAN.

Если исходное значение, необходимое для сравнения, отсутствует,
соответствующий флаг сравнения равен NULL.
has_missing_passenger_count всегда равен TRUE или FALSE.

Неположительная длительность проверяется по исходным датам,
чтобы округление duration_seconds не меняло результат проверки.

Флаги не приводят к удалению записи.
Одна запись может иметь несколько флагов.

## Правила сохранения данных

- Сохраняются записи с пропусками в необязательных полях.
- Сохраняются нулевые и отрицательные значения.
- Сохраняются поездки с датами вне месяца источника.
- Отрицательные суммы не интерпретируются автоматически как возвраты.
- Даты, суммы и другие значения не исправляются на основе предположений.
- Сумма total_amount не называется подтверждённой выручкой
  без отдельного определения показателя.

## Повторная загрузка

Silver хранит одну выбранную версию данных для каждого source_month.

При обработке файла заменяются все записи соответствующего source_month.
Данные других месяцев источника не изменяются.

Замена выполняется одним атомарным коммитом Iceberg.
Отдельные DELETE и INSERT с промежуточным пустым состоянием не используются.

Повторный запуск не добавляет дубли.
При повторной обработке loaded_at может измениться.

Загрузка новой версии файла заменяет предыдущую версию месяца в Silver.
Версии исходных файлов продолжают храниться в raw.

Параллельная загрузка разных версий одного source_month
в первой версии проекта не поддерживается.

## Контроль после загрузки

- Число записей месяца источника совпадает с числом строк входного файла.
- source_file, source_sha256 и source_month соответствуют выбранному файлу.
- Денежные преобразования не создали неожиданных NULL.
- Флаги качества соответствуют своим условиям.
- Повторная загрузка не увеличивает количество записей.
- Обработка одного source_month не меняет данные других месяцев.

## Результаты первичного профилирования

Файл: yellow_tripdata_2024-01.parquet.
Количество строк: 2 964 624.

| Наблюдение | Количество |
|---|---:|
| Начало поездки вне января 2024 | 18 |
| Отсутствует passenger_count | 140 162 |
| passenger_count = 0 | 31 465 |
| trip_distance <= 0 | 60 371 |
| dropoff_datetime <= pickup_datetime | 870 |
| total_amount < 0 | 35 504 |

У одних и тех же 140 162 строк отсутствуют passenger_count,
RatecodeID, store_and_fwd_flag, congestion_surcharge и Airport_fee.
Все эти строки имеют payment_type = 0.

Показатели могут пересекаться; их сумма не равна количеству
уникальных проблемных записей.

Эти значения описывают исследованную версию файла.
Они не являются фиксированными требованиями для других файлов
или обновлённых версий источника.
